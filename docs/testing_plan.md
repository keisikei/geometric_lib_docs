## Цели и задачи тестирования:

**Цель:** убедиться, что функции вычисления площади и периметра фигур возвращают
математически верные результаты на корректных входных данных

**Задачи:**
- Проверить каждую функцию библиотеки вручную по заранее просчитанным наборам данных.
- Автоматизировать проверки с помощью встроенного модуля `unitest`
- выявить дефекты в формулах и зафиксировать их.
- Убедится, что после исправлений все тесты проходят
- разместить тесты в публичном репозитории на гитхабе

## Описание тестируемого продукта:

geometric_lib — это учебная библиотека на Python из четырёх модулей
Каждый модуль содержит две функции: `area` (площадь) и `perimeter` (периметр).

| Модуль | Функции | Формулы |
|---|---|---|
| rectangle.py | area(a, b), perimeter(a, b) | a * b; 2 * (a + b) |
| triangle.py | area(a, h), perimeter(a, b, c) | a * h / 2; a + b + c |
| circle.py | area(r), perimeter(r) | pi * r^2; 2 * pi * r |
| square.py | area(a), perimeter(a) | a * a; 4 * a |

## Область тестирования:

**Тестируем (в области):**
- Все 8 функций: rectangle.area, rectangle.perimeter, triangle.area, triangle.perimeter,
  circle.area, circle.perimeter, square.area, square.perimeter
- Корректные положительные значения (целые и дробные)
- Граничные случаи — нулевые значения
- Возможные частные случаи (квадрат как частный случай прямоугольника, равносторонний треугольник)

**Не тестируем (вне области):**
- Валидация отрицательных чисел и нечисловых типов, т.к. она в библиотеке не реализована
- Проверка корректности геометрических фигур (например, существует ли вообще треугольник с такими сторонами)
- Производительность, безопасность, GUI - у библиотеки таких требований нету

## Стратегия тестирования:

- **Тип тестирования:** функциональное, модульное (unit).
- **Метод:** Сравниваем результат функции с заранее просчитанным вручную значением
- **Техники:** Классы эквивалентности (целые, дробные, ноль) и граничные значения (0)
- **Инструмент:** стандартный модуль `unitest` (Python 3)
- **Порядок работы:** Сначала ручные тест-кейсы -> затем те же проверки автоматизируются ->
  найденные дефекты исправляются -> повторный прогон.
- **Организация тестов:** Один тест-класс на модуль, класс наследуется от `unittest.TestCase`,
  имена тестов начинаются с `test`, проверки через `assertEqual` / `assertAlmostEqual`
  (последний — это для чисел с плавающей точкой, так как pi и деление дают погрешность)
- **Запуск:** `python -m unittest discover -v` из корня проекта
- **Критичность:** Деффект в формуле считается критическим (функция возращает неверный результат).

### Замечания (вне области тестирования)

- Функции не проверяют отрицательные аргументы и нечисловые типы: например,
  `rectangle.area(-3, 4)` вернёт `-12`. 
- `triangle.perimeter` не проверяет существование треугольника (набор 1, 2, 10 даст 13, хотя это не треугольник, т.к. 1 + 2 не больше 10).
